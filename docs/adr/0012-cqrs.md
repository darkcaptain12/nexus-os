# ADR-0012: CQRS with Command and Query Buses

## Status
Accepted

## Context
Mixing reads and writes in the same path leads to contention and complexity. AI agents issue commands (execute trade, send notification) and queries (get portfolio, search memory) with different performance characteristics.

## Decision
Separate command and query paths with dedicated buses, middleware pipelines, and result types.

## Why
- **Read optimization**: Queries can be cached, projected, and read from replicas.
- **Write safety**: Commands go through validation, authorization, and audit middleware.
- **Independent scaling**: Read and write paths can scale independently.
- **Dead letter queue**: Failed commands are captured for investigation, not lost.
- **Middleware**: Cross-cutting concerns (logging, auth, rate-limiting) applied uniformly.

## Consequences
- Eventual consistency between write and read models.
- Projection maintenance adds complexity.
- Two code paths per feature (command handler + query handler).
